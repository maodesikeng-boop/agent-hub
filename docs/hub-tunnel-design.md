# 联机方案（二）：东京当中心，设备用 SSH 连入；手机走东京公网 HTTPS

状态：方案骨架，逐节补。

## 0. 目标和不做的
结论：手机、Mac 都不装 Tailscale；第一期设备用系统 ssh 连东京，第二期手机走东京公网 HTTPS。

## 1. 现成做法和取舍
结论：用系统 OpenSSH（不装 autossh / frp / cloudflared），守护进程自己看着 ssh。

## 2. 总体结构
结论：东京是中心入口；Mac 经 `ssh -R` 把“设备入口”挂到东京回环端口。

## 3. 第一期：SSH 只能转发
结论：每台设备一把专用密钥，authorized_keys 用 restrict + permitlisten/permitopen + 强制命令。

## 4. 第一期：隧道请求的信任边界
结论：守护进程另开“设备入口”（只认设备令牌），隧道只接它。

## 5. 第一期：防 SSRF，设备网址由本机配置
结论：新网址形式 `tunnel:<名字>`，由本机隧道表解析成本地端口，对方不能自报。

## 6. 第一期：谁保持 ssh 常连
结论：守护进程自己起 ssh 并看着。

## 7. 第一期：设置步骤
结论：东京上一条命令装公钥（管理员密钥代装），Mac 上填一次。

## 8. 统一：连法定义在一处
结论：`shared/peer-transport.ts` 一张表。
