# UI standard

Shared interface specification for the Bellwood web workbench (`src/web/`). Colors come from CSS variables in `src/web/styles.css`, and reusable primitives live in `src/web/ui/` and `src/web/components/SettingsList.tsx`. Match every rule below when building or editing screens; if a screen needs a pattern not covered here, update this document first.

## 0. Interface scale

- **Interface scale** (**Settings**, **General**, **Appearance**): `Compact`, `Default`, `Large`, and `XL` (`Segmented`, section 9), saved per browser in `localStorage` (`agent-hub.uiScale`, `src/web/ui-scale.ts`). **`Default` is the default**: a browser that never picked a scale gets it, and a saved choice stays.
- **Root font size (`<html data-ui-scale>` in `src/web/styles.css`, `UI_SCALE_ROOT_PX` in `src/web/ui-scale.ts`)**: `Compact` `100%` (`16px`), `Default` `109.375%` (`17.5px`), `Large` `118.75%` (`19px`), and `XL` `128.125%` (`20.5px`), `1.5px` apart. A bare `html` renders at the `Default` size, so the first paint matches before the app sets the attribute. Type tokens (`--text-*`), `Avatar` sizes, and Tailwind spacing (`rem`) scale proportionally together. A saved scale keeps its name, so a browser that saved `Large` now gets `19px`.
- **Pixel values in this document are at a `16px` root, the `Compact` scale** (`Default` multiplies every `rem` size by `1.09375`, `Large` by `1.1875`, and `XL` by `1.28125`).
- **Shell pane and tier geometry (`src/web/limits.ts`)**: Fixed rail (`SHELL_RAIL_REM = 4.5`), PM column (`SHELL_LIST_REM`, min `13.75`, default `16.5`, max `25`), work panel (`SHELL_PANEL_REM`, min `22.5`, default `40`, max `50`), conversation minimum (`SHELL_CHAT_MIN_REM = 30`) and usable floor (`SHELL_CHAT_USABLE_REM = 20`), and the `shellTierOf()` and `sideBySideMinPx()` breakpoints scale from the active root `rem` (with the `SHELL_FRAME_PX = 6` frame inset and the `SHELL_GAP_PX = 4` gap before the work panel in `px`; the PM column and the conversation join with no gap).
- Never hardcode arbitrary pixel font sizes or widths (`text-[15px]`, `w-[240px]`); use the type tokens in section 3 and Tailwind numeric scales (`w-60`, `max-w-110`). Border radii (section 2.1), `1px` lines, the `40px` top bar that holds the macOS traffic lights, the frame inset and gap, viewport breakpoints (`max-[1100px]`, `min-[720px]:`), and pixel icons stay in `px` (guarded by `src/web/ui-scale.test.tsx`).

## 2. Corners, lines, and depth

### 2.1 Corners

Four radii, each tied to a size of thing. `src/web/styles.css` resets the Tailwind radius scale to these tokens, so `rounded-md` and the stock `rounded-lg` do not exist:

| Token | Value | Element |
| --- | --- | --- |
| `--radius-panel` | `12px` | The panels of the shell: the inlaid block, the white sheets, the PM list's outer corners. A plain circular arc, not a continuous curve |
| `--radius-tile` (`rounded-tile`) | `11px` | Rail tiles (`48px` and `40px` squares) |
| `--radius-sm` (`rounded-sm`) | `8px` | Buttons, inputs, textareas, selects (the base layer gives every `button`, `input`, `textarea`, and `select` this radius), search fields, the composer and its send button, selected and hovered rows, cards, group boxes, ask and thread cards, event strips, code blocks, thumbnails, popovers, menus, dialogs, avatar tiles |
| `--radius-xs` (`rounded-xs`) | `4px` | Chips, tags, and badges (`.tool-badge`, `Closed`, `Offline`, kind tags, attachment and `Worker model` chips, count badges), menu items inside a padded menu, and elements nested inside a padded `8px` parent (segmented cells, switch thumb, progress bars), so inner corners stay smaller than outer ones |

| Element | Rule |
| --- | --- |
| Full-bleed rows inside a group box or a card (`ChoiceRows`, `CollapsibleGroup` triggers, `SettingsNavRow`, event triggers, decision-card `OptionRow` and reply rows) | `rounded-none`: the box or card clips them (`overflow-hidden`), and a rounded hover inside a divided list would notch the divider |
| Where two panels join (the PM list and the conversation sheet, the Settings categories and the open category) | Square: the joined corners are `0` and only the block's outer corners round |
| Status dots, attention dots, radio marks, scrollbar thumbs | Circles (`rounded-full`) |

Pixel craft stays on characters, avatars, sprites, and brand illustrations. `src/web/web-guard.test.ts` allows only `rounded-xs`, `rounded-sm`, `rounded-t-sm`, `rounded-tile`, `rounded-full`, and `rounded-none`.

### 2.2 Lines

Every line on a white or paper surface is **`1px`** and comes from one warm-ink family, defined as alpha so the same token reads as the same line on white and paper:

| Token | Value | Used for |
| --- | --- | --- |
| `--border` (`border-border`, `divide-border`, `bg-border`) | `rgb(110 74 0 / 0.14)` | Structure: header bottoms, dividers, group boxes, cards, popovers, menus, dialogs, media thumbnails, rail and strip dividers, progress-bar tracks |
| `--border-strong` | `rgb(110 74 0 / 0.26)` | Interactive outlines only: inputs, selects, search fields, raised buttons, switch track, radio ring, the composer and the framed reply field |
| `--select-line` | `#e0b03c` | The one selection line (section 4), drawn as a `1px` inset ring |
| `--border-focus` | `#4a4038` | Focus (section 7) |

- The only strokes wider than `1px` are the `2px` keyboard focus outline, the `2px` dashed file-drop target, the `3px` Markdown blockquote bar, and the `2px` halos that separate dots and badges from the surface behind them.
- On the wood the lines are grooves: a `1px` dark line with a `1px` light line under it (`.groove` for a standalone line, `.groove-bottom` for a header bottom), each half `1.4:1` against the wood it sits on (`--groove-dark`, `--groove-light`; the rail uses stronger alphas for its darker wood). Grooves part the list header from the list, `Pinned` from `Project managers` and `Project managers` from `Archived` (inset to the list's `8px` edge, `12px` of space above and below), the Router from the computers on the rail, and the computers from the rail footer (`2rem` wide).
- Panels part by tone and depth, not lines: the PM list sits on the year rings, the conversation and side panel are white sheets, and the frame wood shows in the `4px` gap before the side panel (section 16).
- Containers get the hairline (`--border`); controls get `--border-strong`. A container never takes `--border-strong` to look heavier.
- Chips, tags, and badges are flat fills with no outline (`bg-panel`, or `.tool-badge` honey), as are inline code and log blocks inside a box.
- Do not put a bordered box inside another bordered box. Inside a card, separate parts with spacing or one hairline divider; options and fields inside cards are controls, not boxes.
- `pnpm ui:polish shots` measures these rules on every screen: `machine:thick-line` (a solid line wider than `1.5px`), `machine:box-in-box` (a framed box whose nearest framed ancestor is not a dialog, popover, drawer, or the frame), and `machine:ragged-edge` (row starts in the PM list, side panel, or settings tabs that miss each other by `1.5` to `8px`).

### 2.3 Depth

Depth is reserved for the inlay of the panels in the wood and for things that float, and each has one recipe in `src/web/styles.css`:

| Recipe | Where |
| --- | --- |
| `--inlay-shadow` (`0 0 12px rgb(10 5 2 / 0.376)`) | The rim where the panels sink into the frame wood: `.shell-group` draws it around each block, and each `.shell-sheet` keeps it only in its own rounded corners. The conversation sheet lets it run `4px` into the gap on its right, so the gap reads as deep as the outer rim, and the side panel's rim stops at its own edge |
| `.shell-list::after` | The conversation sheet's shade on the PM list where the two join: the tail of a `-10px 0 20px -8px rgb(10 5 2 / 0.5)` shadow, `0.29` at the joint fading out over `24px`, painted above the rows |
| `row-selected` | Selected row on the year rings (PM rows and settings categories): a flat cream band (`--row-selected` `#fffaf2`) with dark text (`--row-selected-ink` `#24140a`, `17:1`), no ring or shadow |
| `tile-selected` | Selected cell of a segmented control: a white fill, the `1px` `--select-line` inset ring, and `--shadow-tile` (`0 1px 2px rgb(74 46 0 / 0.12)`) |
| `tile-open` | Selected item on white or paper: `--open` fill and the `1px` `--select-line` inset ring, no drop |
| `--shadow-composer`, `--shadow-composer-focus` | The composer, the one field that floats over the stream (section 7) |
| `--shadow-overlay` | Popovers, select menus, the composer menu |
| `--shadow-dialog` | Dialogs (section 10) |

Buttons are flat (section 6). Cards, group boxes, and event strips stay flat. No gradients outside the wood, no frosted glass, no glow.

### 2.4 Wood

The window is wood. Two surfaces carry it, each a base gradient under a texture in `src/web/assets/` that `scripts/render-wood.ts` renders from a fixed seed:

| Surface | Base | Texture | Class |
| --- | --- | --- | --- |
| Frame: behind the rail, the top bar, the panel rims, and the gap before the side panel | `--wood-top` `#5f3302` to `--wood-bottom` `#542d00` (OKLCH L `.37`, hue `61`) down the window | `wood-grain.svg`: sparse vertical grain, dark `#160a03` at `0.068` to `0.129`, each stroke with a `0.048` `#f3cfa3` sheen beside it. A seamless `1200x1000` SVG tile, sharp at every pixel density | `.wood`, fixed to the viewport so the shell and the Settings page line up |
| Year rings: the PM list and the Settings categories | `--rings-top` `#774511` to `--rings-bottom` `#6f3d05` (OKLCH L `.44`) down the panel; the frame to rings step is `1.34:1` | `wood-rings.avif`: latewood lines in `#1a0c03` up to `0.194`, `480x1400` at 2x, fading out at its right and bottom edges | `.wood-rings` |

- Text on the wood is light and measured at the texture's lightest point: list names and the rail's labels use `--list-ink` `#fdf6ec` (`5.95:1`) and `--rail-ink` `#fcf2e5` (`8.72:1`); group headings, list metadata, and the search field's placeholder use `--list-ink-soft` `#eed8c0` (`4.63:1`); offline computers use `--rail-ink-soft` `#c5b099` (`4.62:1`). A translucent fill under text on the rings (`--list-hover`, `--list-field`) stays at `0.07` or less, so the soft ink keeps `4.86:1` on it where the rings are lightest; `src/web/lib/palette.test.ts` holds it at `4.6:1` or more to leave room for gradient dithering.
- `.wood-rings` and `.on-frame` (the rail and the phone tab bar) re-point the shared tokens for what sits on them: lines and fields turn warm white (`--border` `rgb(255 244 228 / 0.12)`, `--border-strong` `0.16`, `--list-field` `0.07`), focus outlines turn light, slot buttons turn translucent warm white, and `--shadow-tile` is off.
- Hover on the wood is a warm white fill: `--list-hover` `rgb(255 240 220 / 0.07)` on the rings, `--rail-hover` `rgb(255 244 228 / 0.1)` on the frame.
- On the top bar, the Router input sits translucent on the frame wood at rest (`--topbar-field` `rgb(255 244 228 / 0.12)` with a `1px` `--topbar-field-line` `rgb(255 244 228 / 0.16)` border; `--topbar-field-hover` `0.15` and `--topbar-field-line-hover` `0.24` on hover) with `--list-ink-soft` (`#eed8c0`) placeholder text (`>= 4.7:1` on hover and `>= 5.1:1` at rest against the lightest grain sheen) and `--rail-ink` (`#fcf2e5`) draft ink. On focus, it turns solid `--background` (`#ffffff`) with `--foreground` ink, `--muted-foreground` placeholder, a `1px` `--border-strong` border, and a crisp `2px` warm-white outer focus ring (`--topbar-focus-ring`, `0 0 0 2px rgb(255 244 228 / 0.35)` with zero blur).

## 3. Type scale, weights, and shell copy

Use only three weights: `400` (default), `500` (`font-medium`), and `600` (`font-semibold`).

All panes and dialogs share **four UI type sizes** defined in `src/web/styles.css` (`@theme`) and registered in `FONT_SIZE_TOKENS` (`src/web/lib/utils.ts`):

| Tier | Class | px at a 16px root | Typical uses |
| --- | --- | --- | --- |
| Micro metadata | `text-xs` | `12` | Timestamps, counts (`tabular-nums`), `Recommended`, rail labels (`500`), badge numerals |
| Secondary text, buttons, and every section heading | `text-minor` | `13.5` | Button labels (`500`), segmented controls, all section and group headings (`500` muted: `Pinned`, `Project managers`, `Archived`, `Workers`, `Completed`, settings groups), work-panel tabs and rows, row descriptions (`leading-snug`), sidebar previews, event strips, `Show more`, inline errors (`text-danger`) |
| Body copy and row titles | `text-body` | `15` (`13.5` in a desktop conversation) | Message prose, settings row titles, `ProjectList` phone PM names (`400`), inputs, selects, ask card questions (`500`), option text (`400`) |
| Pane and dialog titles | `text-title` | `16` | Conversation header name, Info header name, dialog titles (`600`), one step above body text |

**Chat text.** On the desktop, a conversation reads at the size of a Worker thread: `.chat-text` on a PM's conversation, the Router page, and a Worker thread in the work panel points `--text-body` at `--text-minor`, so their messages, Markdown, cards, and composer text set at `13.5px`. Message and Markdown line heights are unitless and Markdown spacing is in `em`, so both follow the smaller text; paddings, row heights, and the `leading-6` (`24px` at a `16px` root) line height of the chat composer and card reply field keep their `rem` values. Settings, dialogs, and the phone keep the `15px` body.

Never use `13px` or `14px` in React components (`src/web/ui-scale.test.tsx`). Markdown headings and code blocks follow section 15.

### Shell copy rules

- All hardcoded UI copy in `src/web/` (headings, row labels, buttons, placeholders, empty states, status words, `aria-label` strings, and tooltips) uses concise **sentence-case English** (`New session`, `Interface scale`, `Sign out all browsers...`), keeping Title Case only for named product surfaces (`Needs You`, `Task Graph`, `Router`). User chat messages, PM names, and Worker titles preserve user input, and user-facing error descriptions come from `src/shared/errors.ts`.
- Write group headings and row titles as short noun phrases (`Mode`, `Effort`) without parenthetical explanations.
- Keep row descriptions to one short sentence stating the consequence, with no trailing period and no editorial nudges (`recommended`, `best for...`).
- Do not repeat the row title on its action button: `New session` pairs with `Start...` (trailing `...` indicates a confirmation step).
- Put `Optional` in the input placeholder rather than appending `(optional)` to the row label.
- Format relative times as `3m ago` or `just now`, archive countdowns as `Deletes in 7d`, and counts as bare numerals (`tabular-nums`).

## 4. Colors and avatars

- **Warm zone palette (`src/web/styles.css`)**:
  - Neutral chrome uses warm paper and sand tokens instead of cool zinc grays or fruit-tinted surface mixes: `--background` (`#ffffff`) for the sheets, cards, and group boxes, `--panel` (`#f7f4ed`) for secondary surfaces inside a sheet (event strips, chips, the settings pane), `--foreground` (`#1c1917`), `--muted-foreground` (`#6f6862`), `--hover` (`#f6f2e9`), and the line tokens in section 2.2.
  - Wood tokens (section 2.4): the rail on the frame (`--rail` `#5f3302`, `--rail-hover`, `--rail-selected` `rgb(255 244 228 / 0.17)`, `--rail-selected-strong` `0.24`, `--rail-ink` `#fcf2e5`, `--rail-ink-soft` `#c5b099`, and the hourglass sand `--sand` `#e6c99a`, `--rail-warn` `#f2b966`, `--rail-danger` `#fe9aa2`), the PM list and Settings categories on the year rings (`--list` `#774511`, `--list-hover`, `--list-field`, `--list-ink` `#fdf6ec`, `--list-ink-soft` `#eed8c0`), and the cream selected band (`--row-selected`, `--row-selected-ink`, `--row-selected-ink-soft` `#7e6550`). `--muted-foreground` stays on white, paper, and field surfaces.
  - `--brand-ink` (`#4a2e00`, `12.5:1` on white) is the warm dark brown of text actions, checks, count chips, and the normal usage bar on white sheets, and the `--primary` outside a PM.
  - **Selection** never changes font weight. On the year rings, `row-selected` is a flat cream band with dark text for PM rows and settings categories; it re-points `--list-ink`, `--list-ink-soft`, `--list-hover`, and `--border-focus` so everything in the row turns dark. On the rail a selected tile takes `--rail-selected` and a selected computer's icon turns solid; the Router bell, the gear, and the hourglass have no solid form, so they take `--rail-selected-strong` while selected or open to stay apart from hover (`--rail-hover`, a fill only). On white or paper, `tile-open` (`--open` `#fff6d6` fill with the `--select-line` ring) marks open side-panel rows, chosen options, and picker grids, and `tile-selected` marks segmented cells. Neutral hover on white uses `bg-hover`.
- **Dynamic PM accent (`--primary` and `--primary-foreground`)**:
  - `src/shared/slimes.ts` decouples 20 fruit slime shapes from 24 palette entries (`blob` for sprite fills, `accent` darkened to >= 4.5:1 WCAG AA contrast against white, verified in `src/web/lib/palette.test.ts`).
  - `AccentScope` (`src/web/lib/accent-scope.tsx`, `display: contents`) wraps each PM conversation, its Worker conversations, the work panel, and in-session dialogs, and sets `--primary`, `--primary-foreground`, and the send colors. Outside `AccentScope` (the left sidebar, `#/router`, global settings, and New PM dialog), `:root` sets `--primary` to `--brand-ink` (`#4a2e00`).
  - **Solid accent (`bg-primary text-primary-foreground`) appears only on**: the single primary button on screen (`Create`, `Save`, or the recommended gate option; `btn-solid`, section 6), checked switch tracks, checked radio marks, the `6px` dot beside the `Needs You` heading, and the file-drop dashed border.
  - **Pastel send (`--send`, `--send-hover`, `--send-press`, `--send-ink`; `pastelSendColors` in `src/web/lib/palette.ts`)**: `Send` and `Stop` in the composer and `Send` in card reply rows take the PM color made light: the hue of its `backdrop`, OKLCH L `.845` and chroma at most `.083` (never above the `blob`'s chroma; chroma drops until the color fits sRGB). Yellows and yellow-greens (hue `70` to `130`) sit at L `.895` and chroma up to `.113`, so they do not read as mustard or olive. Hover lowers L by `.035` (chroma `x1.1`), press by `.065` (chroma `x1.15`). The icon is the same hue dark enough for `7:1` against the pressed fill. Outside `AccentScope` the same rule runs on the Router's honey hue (`#fed782`). With nothing to send the button is `--send-disabled` `#f3efe6` with a `--send-disabled-ink` arrow.
  - **User message bubbles (`bg-bubble-me text-bubble-me-foreground`)**: Mix `--primary` at `12%` (`--mix-bubble-me`) into `#ffffff` with warm dark foreground text (>= 4.5:1 contrast across all 24 colors).
  - **Text links outside Markdown**: Inline secondary text actions use `text-brand-ink` (`#4a2e00`) or `text-muted-foreground hover:text-foreground`. Colored lines appear only on the file-drop target and `--select-line` selections.
  - **Dots**: Status and attention dots are `8px` circles (`size-2 rounded-full`; `10px` on rail tiles) with a `2px` halo in the color of the surface behind them where they sit on a tile, icon, or button. Unanswered asks and waiting turns are green (`bg-status-active`) with no text pill; screen-reader text lives on `aria-label` and `title`. Rail computer dots sit on the device icon's lower-right corner, so they stay beside the icon whether or not the tile is selected; on the wood an offline or connecting computer's dot is `--rail-ink-soft` and a reconnecting one `--rail-warn`. The one attention dot for something to review in Settings (the rail gear, the `Resources` tab, the mobile `Settings` tab and rows) is red (`bg-danger`) on every surface, because amber stays below `3:1` against cream and white.
  - **Chips, tags, and badges** (`.tool-badge` for `Recommended`, `Source`, `Custom`, and `Read-only`; capability kind tags; `Closed` and `Offline`; attachment and `Worker model` chips): flat fills with no outline and no depth, `rounded-xs`, so they read as labels and never as buttons.
- **Avatars (`src/shared/slimes.ts`)**:
  - Inline transparent-background pixel SVGs with no frame.
  - **Project Managers**: 20 fruit slimes paired with any of 24 colors via `SlimePicker` (`Fruit` and `Color` grids).
  - **Workers**: Curled note sprite (`Avatar neutral`) tinted with the owning PM's color.
  - **Router**: Sprout bell (`RouterAvatar`), unscoped warm chrome, preserving source PM avatars on incoming cards and reports.

## 5. Icons

Import all UI icons from `src/web/ui/icons.ts` (`lucide-react` smooth-line 24-grid icons alongside matching smooth-line custom SVGs for `PinFilled` and the five mainstream device types: macOS, Windows, Linux, iPhone, and Android, each with a solid form for the selected computer on the rail (`PlatformIcon solid`): the same outline filled, details cut out; the usage meter draws `QuotaHourglass` on `HOURGLASS_GLASS_PATH` (section 11); composer uses `Plus`, the `ArrowUp` send arrow, `Square`, `FileText`, `Video`, `X`, and `Bot`). Icons inherit text color (`text-muted-foreground` for secondary actions), use `stroke="currentColor"` (`data-icon="line"`), and size via `size-pixel` (`22px` at a `16px` root), `size-pixel-md` (`16.5px`), or `size-pixel-sm` (`12px`). In list group headings and navigation rows, the label after an icon carries `trim-cap` (`text-box: trim-both cap alphabetic`), so flex centering puts the icon on the label's capitals. Never nudge an icon with `translate-y`. Never use emoji as UI icons.

## 6. Control dimensions and tool slots

Controls use two heights: **`36px` default** (`h-9`) and **`32px` small** (`h-8`, reserved for inline row actions and corner controls). On touch devices (`pointer: coarse`), `Input` and `Select` grow to `44px` (`pointer-coarse:h-11`).

| Control | Default | Small | Component |
| --- | --- | --- | --- |
| Button | `h-9 px-4` | `h-8 px-3` (`size="sm"`) | `Button` |
| Icon button | `size-9` (`size="icon"`) | `size-8` (`size="icon-sm"`) | `Button` |
| Text input | `h-9 px-3 border` (`w-60` inside desktop settings rows) | none | `Input` |
| Select | `h-9`, max `260px` (`variant="plain"` for auto-saving rows; Radix UI `Select`) | none | `Select` |
| Textarea | `min-h-24` (borderless auto-sizing inside grouped boxes) | none | `Textarea` |
| Switch | `h-5.5 w-10 border` (`size-4` `rounded-xs` thumb) | none | `Switch` |

- **Button recipes (`src/web/styles.css`)**: every button is flat, with no gradient, inner highlight, drop, or inset shade. `default` and `destructive` use `btn-solid` (solid `--primary` or `--danger`, `brightness(1.08)` on hover and `0.92` while pressed), `outline` uses `btn-raised` (white with a `1px` `--border-strong` line, `--hover` on hover, a step darker while pressed or open), `slot` uses `btn-honey`, and `send` uses `send-button` (section 4). `ghost` has no fill or line (`hover:bg-hover`). Disabled primary buttons use `--send-disabled`.

A standalone MCP server is a plain row with its own switch, its name aligned with the plugin names (`pl-10`).
- **Item rows**: Indented to the plugin name (`pl-10`, `min-h-11`) with the name (description in `title`), a kind tag (`MCP`, `Skill`, or `App`: a flat `rounded-sm bg-panel px-2 text-xs` `500` muted chip), and a `Switch`. MCP servers list before skills. In `Shared` and `This project`, a `13.5px` muted provider list (`Codex, DeepSeek`) follows the tags when not every provider loads the item. A project's own choice shows a `Custom` chip (`.tool-badge`) on the item and its plugin row. On narrow rows the tags and badges wrap below the name instead of truncating it.
- **Saving**: Toggles apply optimistically, queue in order per scope, and fall back to the server state with a `px-4` row error when a save fails; a rescan that finishes after a toggle refetches instead of overwriting it.

The `Info` tab links to project-level settings in its two row groups:

- **`Capabilities` row**: Shown for unarchived PMs on this computer with the `enabled/total` summary; opens `#/pm/<id>/capabilities`.
- **`Worktree setup`**: Opens `#/pm/<id>/worktree`, a borderless auto-sizing `Textarea` (`font-mono text-minor` once non-empty, `No setup command` placeholder). The group header shows a ghost `Clear` when a command is saved and `Cancel` plus a small primary `Save` while edited; `Clear` only empties the draft, and saving blank text clears the command. Drafts survive incoming `project.updated` changes, over-limit or NUL input renders one `RowError` reason and disables `Save`, and archived PMs see the field read-only.

## 24. Updates

`UpdateSettings` (`src/web/components/UpdateSettings.tsx`) renders the `Updates` group under `General` on desktop and the mobile `#/settings/updates` page, reading `GET /api/update` through `src/web/update-model.ts` (one fetch per page load, then hourly through React Query, or every `UPDATE_CHECK_RETRY_MS` while the check fails):

- **Heading**: `Updates` on desktop; mobile shows only the page title.
- **Version row**: `Bellwood vX.Y.Z`, a flat `Source` chip (`.tool-badge`) for source checkouts, and an `outline` `size="sm"` `Check for updates` row action (`Loader2` while checking) aligned with row padding that posts `POST /api/update/check`. The detail line holds the status (`Up to date`, `vX.Y.Z available`, or `Couldn't check for updates`) and a `Release notes` link with a `12px` `ExternalLink` icon.
- **Download row**: Only for bundled installs with a newer release. `vX.Y.Z available` with a small primary `Download for macOS` or `Download for Windows` link (`Download` icon); its detail line moves `Release notes` here and adds `SHA-256` and `Skip this version`. Source checkouts get the status line only, never a download button.
- **Inline actions**: `Release notes`, `SHA-256`, and `Skip this version` use the `Undo` text-action style (`font-medium text-muted-foreground`, `hover:text-foreground hover:underline`, `touch-target`) with `gap-x-3` between them. Downloads and release links open in the system browser (`target="_blank"`).
- **Skip this version**: Stored per version in `localStorage` (`agent-hub.update.dismissed`); it hides the rail `Update` slot (section 6) and the mobile attention dot until a newer release appears, while the download row stays available.
- **Mobile entry**: An `Updates` `SettingsNavRow` in the `General` group with the cached `vX.Y.Z` summary and the red attention dot (section 4) while the rail reminder would show; it reads only the query cache, so `#/settings` still makes no requests.

## 25. Resources

`ResourcesSettings` (`src/web/components/ResourcesSettings.tsx`) renders the `Resources` tab in desktop `SettingsDialog` and the mobile `#/settings/resources` page (`src/web/mobile/settings/ResourcesPage.tsx`), reading `GET /api/resources` through `src/web/resources-model.ts`:

- **Attention indicator**: The red attention dot (section 4) marks the rail `Settings` tile, the desktop `Resources` tab, and the mobile `Resources` `SettingsNavRow` whenever at least one held resource has `keptAt === null`. The mobile `#/settings` home reads only the React Query cache (`useCachedResourcesSummary`), so it issues zero network requests.
- **Computer scope**: When two or more computers are online, a top `SettingsGroup` offers a borderless `Select variant="plain"` computer picker so each computer's disk, branches, and processes can be inspected through device proxy routes.
- **Needs review**: Shown above `Summary` only when unacknowledged held items exist. Each row shows the item label, an `8px` round `bg-caution` status dot, spaced plain-language metadata (`gap-x-3`, never middle dots) with reason (`Unsaved file edits`, `Untracked files`, `Unmerged branch`, `Leftover temp folder`, `Leftover background process`, etc.), project name, size (`tabular-nums`), and up to 5 sample paths (`font-mono text-xs`), paired with `outline` `Keep` and danger-tinted `Delete…` (or `Stop…` for processes) actions.
- **Summary**: A `SettingsGroup` (`Refresh` and `Clean up` actions aligned cleanly in its header) with four plain-language rows: `Chat & app data`, `Files & workspaces`, `Worker workspaces` (`N active`, `N ready to clean`, `N to review`), and `Background processes` (`N running`, `N leftover`). Routine quota denominators stay hidden below `RESOURCES_WARN_RATIO` (`80%`); items at or above `80%` display the cap and a caution indicator. A default-collapsed `CollapsibleGroup` (`Storage breakdown`) lists per-directory and humanized database category totals on demand (never raw SQLite table names).
- **Kept**: A default-collapsed `CollapsibleGroup` holding items the user marked `Keep`, with `Allow cleanup` and `Delete…` / `Stop…` actions.
- **Delete/Stop confirmation**: Clicking `Delete…` or `Stop…` always opens a `max-w-110` `DialogContent` showing the item path or branch, reason, size, sample paths, an optional `Also delete branch` switch for held worktrees, `Cancel` (`outline`), and one destructive `Delete` / `Stop process` (`variant="destructive"`) button.

## 26. Pins

`PUT /api/pms/:id/pin` persists per-PM pins per computer (`pm_pins` SQLite table, `pinnedAt` epoch ms):

- **`Pinned` group (`ProjectList` and `projectListOf`)**: Renders above `Project managers` in the `column` and `page` layouts only when at least one unarchived PM on the selected computer has `pinnedAt !== null`. Order follows `pinnedAt` ascending (oldest pin first, tie-broken by `pm.id` ascending).
- **Where pins toggle**: On desktop `ProjectList` rows via the `.row-shortcuts` `Pin` / `PinFilled` button. On the mobile Projects page, the same control stays visible with a 44px touch target. The Info summary has a pin button beside the project manager’s name, including in the desktop stack tier. Archiving preserves `pinnedAt` (so unarchiving restores the pin) without displaying archived PMs in `Pinned`; offline/read-only remote views disable pin toggling.
