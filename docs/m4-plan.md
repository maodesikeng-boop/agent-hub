# M4 计划：“等你”提醒

> 状态：用户 2026-11-04 看过并改了一轮，第 4 节的问题都已经定了。
> 依据：[prototype-design.md](prototype-design.md)（下文简称“设计”）第 3.5、3.7、5.3、7.5 节，第 11 章和里程碑表；[m0-report.md](m0-report.md) 实验 4、8；[m3-plan.md](m3-plan.md)；main 上 `ad65a3e` 的 M3 实现；Claude Code 官方文档（链接在文末）；2026-11-04 用 `claude` 2.1.314 + haiku 实测了两次（第 2.1 节）。
> 用户 11-04 定的原则：**系统只提供编排的能力，不写死工作流程**。原话：“它只需要编排工作就可以了，至于怎么编排，agent 自己思考，每个用户情况都不一样，我有我的 agents.md”。所以 M4 只做一件事：agent 停下来等用户的时候，能提醒到用户。agent 什么时候该问、问什么，系统不管。
> 写于 2026-11-04。

## 1. 范围

**M4 要解决的**：一个项目经理和它的 Worker 都停了下来，接下来要用户说话，这时能提醒到用户，用户点一下就回到那个会话。

**做完用户能看到什么**：

1. 用户交代完一件事就切到别的应用。等项目经理和它派的 Worker 都做完、停下来，弹出一个系统通知：“<项目经理名> 等你”。
2. 左栏这个项目经理那一行显示“等你”，浏览器标签页的标题变成“(1) agent-hub”。
3. 点通知，浏览器回到前台，打开的就是这个会话；“等你”和标题里的数字随之消失。
4. 用户一直看着这个会话的时候，不弹通知。

**最小的那条路**

| 步骤 | 怎么做 |
|---|---|
| 判断“等你” | 只在网页里算，用的是网页已经有的会话状态和消息（第 2.2 节）。不用 agent 配合，不解析回复的内容，守护进程也不改 |
| 左栏和标题 | 在“等你”的项目经理那一行显示“等你”；标签页标题前面加上在“等你”的项目经理个数 |
| 通知 | 用浏览器的通知接口。网页要开着，标签页在后台也行。点通知时网页切到前台，并打开对应的会话（第 2.3 节） |

**M4 不做**（各写一句为什么）

- **被拦下的操作做成卡片、“允许”按钮、给 agent 发同意**：被拦了，由 agent 自己在对话里说；Worker 做不下去，会在汇报里写，由项目经理告诉用户。系统不插手（11-04 用户定）。
- **挂起等批准的 `PermissionRequest` 钩子**（设计 5.3、7.5 节）：上一条已经不做了；而且在 `auto` 档、`-p` 模式下，几乎没有操作会走到这个钩子（第 2.1 节）。
- **单独的收件箱页、四档分组**：左栏有“等你”，点进去就是会话，够用了。
- **审批流程、红线设置页、`policy.json`**：用户的原则是少加硬限制。现在唯一的硬限制，Worker 不能写记忆，已经在 `policy.ts` 里了。
- **`hub ask` 命令、“需要你回复”的标记**：“等你”靠的是会话都停下来了，agent 不用学新命令，也不用照固定格式写。
- **规定 agent 什么时候必须问用户**：照 11-04 的原则，由 agent 按 `AGENTS.md` 自己判断。
- **改提示词**：“等你”不需要 agent 配合。提示词由另一个 PR 在改，M4 不碰 `src/daemon/prompt.ts`。
- **网页关着时用 `osascript` 兜底弹通知**：M0 实测这种通知点了只会打开“脚本编辑器”，跳不回网页。
- **勿扰时段、通知开关、未读数**：先用着看看吵不吵，再说。

## 2. 关键决定

### 2.1 为什么不做权限钩子（查到的现状）

这一节只是记下查到的东西，以后要加的时候有个依据：

- 分类器拦下的操作，不会触发 `PermissionRequest`：Claude 收到原因，接着往下干（[permission-modes][cc-modes] 的 How the classifier evaluates actions 一节第 4 步）。这时触发的是 `PermissionDenied` 钩子，它只能回 `retry: true`，不能撤销这次拦截（[hooks][cc-hooks] 的 PermissionDenied 一节）。
- `-p` 模式下，连续拦 3 次或累计 20 次之后，也不会改成问人：“the action doesn't run and Claude keeps working”（[permission-modes][cc-modes] 的 Repeated-block thresholds 一节）。
- 用户在对话里点名同意，分类器会认（同一页的 Approvals you state in conversation 一节）。所以 agent 被拦了来问，用户回一句就行，不需要系统再做什么。
- 实测（2026-11-04，`claude` 2.1.314 + haiku，`--permission-mode auto`，在一个一次性仓库里，远端是本地的裸仓库），两次都没被拦：
  - 用户直接让它 `git push --force`：放行了；
  - 强推的指令写在文件里：它自己停下来，在回复里问用户。

### 2.2 “等你”怎么算

在网页里算。一个项目经理同时满足下面四条，就算在“等你”：

1. 它的会话和它所有 Worker 的会话，`activity` 都是 `idle`。Worker 的会话用现成的 `runningWorkerCount` 那套判断；
2. 它的会话里没有 `queued`、`delivered`、`processing` 状态的消息；
3. 最后一条消息不是用户发的；
4. 用户上次看这个会话之后，又有了新消息。

- **“上次看”**：网页在前台、正开着这个会话的那个时刻。时间存在浏览器的 `localStorage` 里，网页重开以后还在。
- **要停稳了才算**：上面四条要持续满足 `WAITING_SETTLE_MS`（3 秒）。这是为了避开 Worker 刚汇报、项目经理还没开始处理的那一瞬间，那时看上去所有会话都停着。
- **好处和坏处**：不用 agent 配合，问什么、怎么问都行；坏处是项目经理只是做完了、没有提问，也会提醒一次。嫌吵再改。
- **以后**：要在网页关着时也能提醒，再把这个判断挪到守护进程里。

### 2.3 通知

- **用什么弹**：浏览器的通知接口（`new Notification`）。M0 实验 8 证实 `127.0.0.1` 算安全来源，可以申请通知权限。界面端口固定是 4317（`DEFAULT_UI_PORT`），所以授权一次以后一直有效。
- **什么时候弹**：一个项目经理从“不算等你”变成“等你”时，弹一次。
  - 用户正看着这个会话时不弹：网页在前台，选中的也正是这个会话。
  - 刚打开网页时本来就在“等你”的，不弹，只在左栏显示。
  - `tag` 用项目经理的编号，同一个项目经理只留最新的一条通知。
- **点了以后**：`window.focus()`，再选中那个项目经理的会话。M0 没能自动验证点通知能不能跳回网页，所以放进验收第 4 步，让用户手动看。
- **申请权限**：浏览器要求由用户的操作来触发申请。所以通知权限还是“没问过”时，左栏底部显示一个“开启通知”按钮，点了才申请。用户拒绝过，就不再显示。
- **放在哪**：判断“等你”、`localStorage`、通知相关的代码，都放在 `src/web/notify.ts`；可调的数（`WAITING_SETTLE_MS`）放在它的开头。

## 3. 拆分

只有 1 块：一个 Worker、一个 PR，只改网页。守护进程、`src/shared/`、提示词都不改。

| 东西 | 放在哪 |
|---|---|
| 判断“等你”、“上次看”（`localStorage`）、弹通知、点通知后打开会话、`WAITING_SETTLE_MS` | `src/web/notify.ts`（新） |
| “这个项目经理在不在等你”的选择器 | `src/web/selectors.ts` |
| 左栏的“等你”、“开启通知”按钮 | `src/web/components/Sidebar.tsx` |
| 接线：标签页标题、选中会话时记下“看过了”、点通知后切换会话 | `src/web/App.tsx`（需要的话还有 `useHub.ts`） |
| 测试 | `src/web/notify.test.ts`（新）、`src/web/m4.test.tsx`（新） |

不碰：`src/daemon/`（包括另一个 Worker 在改的 `prompt.ts`）、`src/shared/`、`test/e2e/`、`test/smoke/`。

### 测试表（TDD，先写测试；用 jsdom，把 `Notification` 换成假的，用假时钟）

| 测什么 | 期望 |
|---|---|
| 停稳了才算 | 项目经理和它的 Worker 都停下来 3 秒以后，才算“等你” |
| 停一下又忙 | 只停了 1 秒，又有新消息排队或者会话又忙起来：不算“等你” |
| 有 Worker 在跑 | 项目经理停了，但还有一个 Worker 不是 `idle`：不算 |
| 有消息在处理 | 项目经理的会话里有 `queued`、`delivered` 或 `processing` 的消息：不算 |
| 最后一条是用户的 | 不算 |
| 看过了 | 打开这个会话、网页在前台：不再算“等你”；之后又来了新消息并且停稳：重新算 |
| 网页重开 | `localStorage` 里的“上次看”还在，看过的不会又显示“等你” |
| 左栏和标题 | 在“等你”的那一行显示“等你”；标题是“(N) <产品名>”；没有时标题没有括号 |
| 弹通知 | 从“不算”变成“等你”时弹一次，标题和正文对；同一个项目经理的通知 `tag` 相同 |
| 不弹 | 网页在前台并且正开着这个会话；刚打开网页时本来就在“等你” |
| 点通知 | 调 `window.focus()`，选中那个会话，“等你”消失 |
| 申请权限 | 权限是 `default` 时显示“开启通知”，点了调 `requestPermission`；`granted` 或 `denied` 时不显示 |
| 没有通知接口 | 浏览器没有 `Notification`：不报错，左栏和标题照常 |

**端到端、真 `claude` 冒烟**：都不加。M4 只改网页，判断用的是 M1～M3 已经有端到端测试的会话状态和消息状态；也不涉及 `claude` 的任何行为。

## 4. 要用户拍板的问题

都已定（用户 2026-11-04）：

1. **被拦下的操作**：不做卡片，交给 agent 在对话里说；Worker 做不下去，在汇报里写，由项目经理告诉用户。
2. **Worker 被拦下时问谁**：随上一条拿掉了，不再需要定。
3. **“等你”的判定**：照第 2.2 节，项目经理和它的 Worker 都停下来就算。嫌吵再改。
4. **网页关着的时候**：不用 `osascript` 兜底，只用浏览器通知。

还没定的：无。

## 5. 验收

M4 的 PR 合并后，用户在本机：

1. `pnpm install && pnpm build && pnpm check`：全部通过。`pnpm start`，打开界面，M3 的项目经理、Worker 和聊天记录都在。
2. 左栏底部点“开启通知”，在浏览器弹出的窗口里点允许。按钮随之消失。如果没有弹出窗口，到“系统设置 → 通知 → Google Chrome”看看是否允许了通知。
3. 跟一个项目经理说一件要派 Worker 的小事，然后切到别的应用。等它和 Worker 都做完：
   - 弹出“<项目经理名> 等你”的通知；
   - 左栏它那一行显示“等你”；
   - 标签页的标题是“(1) agent-hub”。
4. 点通知：浏览器回到前台，打开的就是这个项目经理的会话，“等你”和标题里的数字都没了。
5. 再说一句，然后一直看着这个会话，等它做完：不弹通知。
6. 两个项目经理同时干活，切到别的应用：哪个先停下来，就先弹哪个的通知；标题里的数字是正在“等你”的个数。
7. 关掉网页再打开：已经看过的不显示“等你”；还没看的照样显示，但不会再补弹一次通知。
